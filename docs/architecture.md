## 1. Стек

Vue 3 + TypeScript + Vite + Element Plus + Pinia + Vue Router + Vue Query (Tan Stack) + ECharts (если понадобятся графики) + ~~Leaflet (карта)~~

Тестирование: Vitest + Vue Test Utils. Playwright — опционально.

Сборка: статика за Nginx.

## 2. Маршруты, данные и layout

**AppLayout:** Sidebar (навигация) + Header (уведомления, кнопка открытия формы, пользователь) + RouterView.

**AuthLayout:** только RouterView.

| Маршрут      | Страница         | Layout     | Данные           |
| ------------ | ---------------- | ---------- | ---------------- |
| /login       | Вход             | AuthLayout | Bearer           |
| /predictions | Список прогнозов | AppLayout  | `prediction_log` |
| /alarms      | Журнал событий   | AppLayout  | `raw_events`     |
| /403         | Нет доступа      | AppLayout  | -                |
| \*           | 404              | AppLayout  | -                |

**Если будут геоданные:**

| Маршрут | Страница       | Layout    | Данные                            |
| ------- | -------------- | --------- | --------------------------------- |
| /map    | Карта датчиков | AppLayout | `dim_channels` + `prediction_log` |

где,

/map — отдельная страница
├── точки датчиков
├── цвет = макс. риск прогноза
└── клик → карточка датчика
├── объект (если связь есть)
├── прогнозы по датчику
└── события по датчику

## 3. API

| Метод                              | Что                                                                                                         |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `GET /predictions`                 | Список прогнозов (сортировка`computedAt DESC, id DESC`)                                                     |
| `GET /predictions/:id`             | Детали прогноза (для боковой панели)                                                                        |
| `GET /alarms?from=...&to=...`      | Список событий (`from: required`, `to: required`, максимум 31 день, сортировка`eventTs DESC, eventId DESC`) |
| `GET /alarms/:eventId?eventTs=...` | Детали события (для боковой панели)                                                                         |
| `POST /decisions`(с `requestId`)   | Решение диспетчера                                                                                          |
| `GET /reference-data`              | Справочники                                                                                                 |
| `GET /dashboard`                   | Сводка прогнозов\событий                                                                                    |
| `GET /objects`                     | Объекты                                                                                                     |
| `GET /map`                         | (заглушка)                                                                                                  |
| `GET /notifications/stream`        | SSE                                                                                                         |

GET /notifications/stream

├── fetch с ReadableStream
├── event: critical-predictions
├── data: PredictionPage (items, limit, offset, hasMore)
├── каждые 5 секунд, включая первый снимок
├── replace state, не append
├── дедупликация уведомлений по prediction.id
├── reconnect через 5 секунд
├── нет Last-Event-ID
├── стрим живёт 30 минут
└── заголовок Authorization: Bearer <token></token>

## 4. Авторизация

1. Демо токен: demo-local-token.
2. Фронт хранит токен (localStorage\sessionStorage).
3. Все REST-запросы: Authorization: Bearer <token></token>.
4. SSE: потоковый fetch с Authorization.
5. 401 → показать «нет доступа», не редирект на `/login`.

## 5. Справочники

`GET /reference-data` при старте
├── actions → выпадающий список действий
├── reasons → выпадающий список причин
├── incidentTypes → фильтр по типам
├── riskThresholds → пороги (medium, high)
└── predictionStatuses → NEW / REVIEWED

## 7. Форма решения деспетчера

- решение по прогнозу — можно,
- решение по тревожному срабатыванию — можно,
- решение по нетревожному срабатыванию — **нельзя** .

Кнопка «Создать решение» в карточке события показывается только если `isAlarm === true`.

Валидация:

- actionCode, reasonCode — обязательны
- если reasonCode === 'OTHER' — comment обязателен

Идемпотентность:

- При повторной отправке используется тот же requestId (UUID).
- Новый requestId при повторной отправке → дубль.
- 409 → решение уже было изменено.

### Что НЕ делаем сейчас

- Карту — координат нет
- Связь канал→объект — связи нет
- Отдельный журнал ОДС — не отделён
- Графики — не по чему рисовать
- Админку, импорт — следующий этап
