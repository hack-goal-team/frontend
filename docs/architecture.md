# Архитектура интерфейса

Документ описывает реализованное приложение в `src/`. Контракт HTTP API
хранится в `backend/docs/openapi-frontend.yaml`; спецификация запущенного
Java-приложения доступна через `/v3/api-docs` и `/swagger-ui.html`.

## Состав

`src/app/main.ts` создаёт Vue-приложение, подключает Pinia, Vue Router и
TanStack Vue Query. Если в режиме разработки задано `VITE_USE_MOCK=true`,
до запуска приложения включается MSW. Код разделён следующим образом:

- `src/pages/` — страницы;
- `src/modules/` — API, типы, запросы и состояние предметных областей;
- `src/shared/api/` — общий HTTP-клиент, cookie и CSRF;
- `src/mocks/` — ответы для автономной разработки;
- `src/app/layouts/` — оболочки страницы входа и защищённых страниц.

Серверные списки и карточки загружаются через Vue Query. Пользователь,
справочник и уведомления хранятся в Pinia. Интерфейс читает готовые прогнозы
через бэкенд и не вызывает модель напрямую.

## Маршруты

| Путь                     | Страница                          | Право             |
| ------------------------ | --------------------------------- | ----------------- |
| `/login`                 | Вход                              | Публичный маршрут |
| `/dashboard`             | Сводка рисков                     | `PREDICTION_READ` |
| `/predictions`           | Журнал прогнозов                  | `PREDICTION_READ` |
| `/objects`               | Реестр объектов                   | `PREDICTION_READ` |
| `/objects/:id`           | Граф объекта                      | `PREDICTION_READ` |
| `/import`                | Загрузка журнала                  | `SETTINGS_WRITE`  |
| `/reports`               | Заглушка                          | `REPORT_READ`     |
| `/settings`              | Настройки: параметры и интеграции | `SETTINGS_WRITE`  |
| `/audit`                 | Журнал аудита                     | `AUDIT_READ`      |
| `/403`, неизвестный путь | Сообщение об ошибке               | Требуется сессия  |

Страж в `src/app/router/index.ts` получает профиль через `GET /auth/me`,
направляет пользователя без сессии на `/login?redirect=...` и проверяет
право для защищённого маршрута. Бэкенд повторно проверяет право и область
видимости каждого запроса; клиентская проверка управляет только навигацией.

## API и сессия

`src/shared/api/http.ts` создаёт Axios-клиент с `baseURL=VITE_API_URL` и
`withCredentials=true`. Для `POST`, `PUT`, `PATCH` и `DELETE` он добавляет
`X-XSRF-TOKEN` из cookie `XSRF-TOKEN`, если она есть. Импорт журнала
отправляется в `POST /admin/import/journal`; состояние задания читается
через отдельный запрос.

В карточке прогноза пользователь с правом `DECISION_CREATE` может создать
решение. Форма берёт причины из `/reference-data`, требует комментарий там,
где его требует причина, и отправляет `requestId` для идемпотентного повтора.
После успешного ответа обновляются запросы прогноза и сводки. Сейчас форма
создаёт решение только для цели типа `PREDICTION`.

Страница `/settings` читает параметры через `GET /settings` и сохраняет
через `PUT /settings`: срок действия решения, окно свежести показания и
пороги риска `MEDIUM`/`HIGH` (в контракте — вероятность 0…1, в форме —
проценты). Горизонт прогноза отдаётся в ответе только для чтения. Блок
«Интеграции» запускает внеочередную загрузку данных из внешних систем:
`POST /admin/weather/refresh`, `/admin/registry/refresh`,
`/admin/ods/refresh`. Ручки синхронные, отвечают итогом загрузки; `409`
означает уже идущее обновление, `502` — недоступность источника. Каждый
вызов пишется в аудит на бэке.

Страница `/audit` читает журнал через `GET /audit` с фильтрами `from`, `to`
(интервал `[from, to)`), `actor`, `category` и повторяющимся `action`.
Ответ — страница `PageAuditEntry` с `hasMore` без `X-Total-Count`, поэтому
список догружается кнопкой «Показать ещё», а не постраничной навигацией.
Словарь категорий и действий бэк справочником не отдаёт: в фильтрах это
коды с ручным вводом, записи показываются как есть, `payload` раскрывается
в строке таблицы.

Обработка `401` при обычном API-запросе пока не перенаправляет браузер на
вход: в перехватчике оставлен TODO. Страж маршрута проверяет сессию при
навигации. Это ограничение следует учитывать при испытании истёкшей сессии
на уже открытой странице.

## Уведомления

`src/modules/notifications/useSse.ts` подключается к
`GET /notifications/stream` с cookie-сессией и принимает событие
`critical-predictions`. При переподключении обновляются запросы прогнозов,
сводки и карты рисков объектов. После ошибки или закрытия потока клиент
делает новую попытку через 5 секунд. Событие содержит снимок активных
прогнозов, а не гарантированную доставку каждого изменения.

## Конфигурация и сборка

`VITE_API_URL` задаёт базовый путь API; при совместном размещении —
`/api/v1`. В режиме разработки `VITE_API_TARGET` включает прокси Vite для
`/api`, если `VITE_USE_MOCK=false`. MSW работает только в dev-режиме.
`VITE_USE_MOCK_DELAY=false` отключает искусственную задержку ответов MSW.
`VITE_API_TOKEN` указан в шаблоне окружения, но HTTP-клиент его не читает.

`npm run build` запускает `vue-tsc -b` и Vite, результат находится в
`dist/`. Проверки: `npm run lint`, `npm run typecheck`,
`npm run format:check`, `npm run test:run`. Роутер использует History API;
веб-сервер должен возвращать `index.html` для путей приложения и
проксировать `/api/` к бэкенду. Для SSE на прокси отключают буферизацию.

## Ограничения реализации

Страница `/reports` показывает «Раздел в разработке». Отдельного маршрута
журнала срабатываний и кнопки запуска обучения в проверенном коде нет.
Карта местности не предусмотрена: исходный реестр не содержит координат.
Наличие маршрута `/objects/:id` означает граф объекта в интерфейсе, а не
географическую карту.
